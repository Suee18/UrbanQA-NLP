Overview

What the project does

UrbanQA builds a retrieval-based question answering system over a multi-city knowledge corpus. Given a natural language question about any covered city — its history, geography, governance, economy, landmarks — the system retrieves the most relevant passages and extracts a precise answer span. Every stage of the standard NLP pipeline is implemented from scratch, from raw data collection to evaluation.

NLP Pipeline

Eight-stage pipeline

Every step justifies its place. No black-box shortcuts — each module is implemented, analyzable, and replaceable.

01
Data Collection Collection

Scrape Wikipedia articles for 20+ target cities using the Wikipedia API. Supplement with city tourism portals, municipal "About" pages, and optionally news headlines via NewsAPI or RSS feeds. Store raw HTML and plain text separately for reproducibility.

wikipedia-api BeautifulSoup4 newspaper3k requests NewsAPI
02
Preprocessing & Segmentation Processing

Clean raw text (strip markup, fix encodings, remove boilerplate). Sentence-segment each article, then split into overlapping fixed-size passages (e.g. 3 sentences with 1-sentence stride). Tokenize, lowercase, and remove stopwords for sparse representations. Tag each passage with its source city as metadata.

spaCy NLTK ftfy langdetect
03
Linguistic Analysis (NER + POS) Processing

Run Named Entity Recognition to tag city-specific entities: locations (LOC), organizations (ORG), people (PER), dates (DATE), and geopolitical entities (GPE). Run POS tagging and dependency parsing. Store entity annotations per passage — used later for answer validation and query matching.

spaCy en_core_web_lg Stanza flair
04
Indexing & Representation Modeling

Build two parallel indexes over the passage corpus. (1) Sparse: TF-IDF weighted BM25 index for keyword-based retrieval. (2) Dense: encode all passages with a sentence transformer into a FAISS vector index for semantic retrieval. Both indexes are queryable independently for ablation.

rank-bm25 sentence-transformers FAISS all-MiniLM-L6-v2
05
Query Processing Modeling

Analyze the incoming question. Classify question type (what / where / when / who / how many) using a rule-based or lightweight classifier. Extract city entity from query using NER — this identifies which city the question is about and narrows retrieval to that city's passages. Expand query with city synonyms if needed.

spaCy regex rules GeoNames
06
Passage Retrieval Modeling

Filter index to the identified city's passages, then retrieve top-k candidates using BM25 or dense search (or both). Combine with Reciprocal Rank Fusion for a hybrid retriever. Re-rank candidates using a cross-encoder if compute allows. Return top-3 passages for answer extraction.

rank-bm25 FAISS cross-encoder/ms-marco RRF
07
Answer Extraction Modeling

Feed the top retrieved passage + question into a pre-trained extractive QA model (DistilBERT or RoBERTa fine-tuned on SQuAD 2.0). The model returns a start/end span. Validate the span type against the expected answer type (e.g., a "when" question expects a DATE entity). Return the answer with confidence score and source passage.

transformers deepset/roberta-base-squad2 distilbert-base-squad2
08
Evaluation Evaluation

Evaluate against a manually annotated gold set of 100+ city QA pairs. Measure Exact Match and token-level F1 for answer quality. Measure Recall@k for retrieval. Compare BM25-only vs. dense-only vs. hybrid. Perform error analysis: categorize failures by city, question type, and pipeline stage.

datasets evaluate pandas matplotlib

Features

What makes it complete

Key design decisions that give this project depth and justify every pipeline stage.

🌍
Multi-city corpus
20+ cities spanning multiple regions and languages. The broader corpus forces the system to disambiguate cities (Paris TX vs Paris FR) and handle varied writing styles — a richer NLP challenge than a single-city setup.
🔍
Dual retrieval (sparse + dense)
BM25 for keyword precision, sentence-BERT embeddings + FAISS for semantic recall. Running both as an ablation gives you a comparison experiment that strengthens the evaluation section of your report.
🗺️
City identification in query
The query processor uses NER to detect which city a question refers to, then narrows retrieval to that city's passages. This is a novel sub-task that adds a full NLP reasoning step before retrieval even begins.
🏷️
Question type classification
Classifying questions (what / who / when / where / how many) lets the system validate that the extracted answer span has the expected entity type — a lightweight post-processing step that reduces obvious errors.
📊
Rigorous evaluation
A manually built gold QA set of 100+ pairs — not borrowed benchmarks. Evaluation covers both retrieval quality (Recall@k, MRR) and answer quality (EM, F1), with a breakdown by city and question type.
🔬
Error analysis module
Failures are categorized by stage: retrieval miss vs. extraction error vs. city detection failure. This lets you write a substantive analysis section and propose targeted improvements — which professors love.
♻️
Modular architecture
Each pipeline stage is a standalone module with a clean interface. You can swap out the retriever or the QA model independently — great for ablations and easy to present as a system diagram.
🚀
Streamlit demo (stretch)
A simple UI where a user types a city question and sees the retrieved passage + highlighted answer span. Takes ~1 day to build on top of the finished pipeline and makes the final presentation memorable.

Stretch goals
  • Arabic language support — scrape Arabic Wikipedia for Arab cities; add multilingual-e5 as the dense retriever; evaluate on Arabic QA pairs using TyDi QA as reference.
  • Fine-tune on city domain — create a small city-specific SQuAD-style dataset (500+ spans) and fine-tune DistilBERT; compare against zero-shot performance.
  • Generative answer mode — use a small seq2seq model (T5-small) to generate a fluent answer from the retrieved passage instead of span extraction; compare both modes.
  • Real-time news integration — add a live NewsAPI feed so the system can answer questions about recent city events, not just static Wikipedia knowledge.
